# Bring Passenger 0.4.3–0.4.6 into Wayfarer

**Status:** Phase 1 applied on branch `passenger-0.4.6` (2026-11-27), with Avalonia held at 12.1.6 (see
[Phase 1 outcome](#phase-1-outcome)), and Phase 2 (see [Phase 2 outcome](#phase-2-outcome)). Phases 3 and 4 not
started.

The vendored copy sits at Passenger **v0.4.2** (`8a1df7e4`, `vendor/passenger.json`). Upstream has since released
**v0.4.3, v0.4.4, v0.4.5 and v0.4.6** (latest, 2026-11-27): 286 commits, 644 files. Six more commits on upstream `main`
after v0.4.6 touch no kept path, so the target is the **v0.4.6 tag**.

Most of what those releases announce is .NET work (C#, Roslyn, NuGet, Aspire, Godot, WPF, mobile, the .NET debugger)
that lives in projects Wayfarer never vendored. What reaches Wayfarer arrives in three ways:

| Route | What it carries | Effort |
|---|---|---|
| **A. `import-passenger.py update v0.4.6`** | 61 changed files in the kept libraries (Core, Text, Editor, Terminal, Vcs, theme files, grammars, package pins). They work as soon as they build. | Small: 1 conflict, 4 compile errors (measured below) |
| **B. Shell copies** (`copies --to v0.4.6`) | 62 hand-adapted files in `src/WayfarerWanderer.App` whose Passenger originals changed. Each needs a read and a port. | Medium: spread over the phases below |
| **C. New features** | Upstream features whose Passenger.App code Wayfarer never copied: portable copies, the Windows update retry, `.gitignore`/`.gitattributes` assists. | Larger, each optional |

## What was measured

A trial ran in a throwaway worktree (main untouched):

- **`update v0.4.6`**: 52 files taken as upstream has them, 8 three-way merged with Wayfarer's changes, **1 conflict**:
  `THIRD_PARTY_NOTICES.md`. Wayfarer's java/groovy/Kotlin grammar entries meet upstream's MagicPython bump from VS Code
  1.144.0 to 1.148.0. Fix: keep Wayfarer's lines and take upstream's version line.
- **Restore** with `--force-evaluate` succeeds (Avalonia 12.1.6 → 12.2.0, Svg.Skia 5.2.4, ReactiveUI 28).
- **Build: 4 errors**, all from two library API changes:
  1. `Program.cs:35`: `CodeFonts.Install` now also takes a `reads` check (#2291, a Type1 font breaking the font lists
     on Linux). Port `PlatformWidths.Readable` from upstream's `Theme/PlatformWidths.cs` and pass it.
  2. `Shell/Vcs/VcsController.cs:1655,1701,1720`: `Git.UnstageAsync` takes renames separately (#2143, an unstaged move
     keeps its move), and `IndexEntryAsync`/`PutIndexEntryAsync` became batched `IndexEntriesAsync`/
     `PutIndexEntriesAsync` (#2145, staging 600 files went from 25 s to a fraction of a second). Port
     `StageAsync`, `IndexEntriesAsync` and `PutIndexEntriesAsync` from upstream's `Vcs/VcsController.cs`.
- With those two ports the trial builds with **0 errors, 0 warnings**.
- **Tests:** see [Trial test run](#trial-test-run).

## Phase 1: update the vendored copy to v0.4.6 (one commit)

The same steps as the v0.4.2 bump (`9330941`):

1. `python3 tools/import-passenger.py update v0.4.6`
2. Resolve `THIRD_PARTY_NOTICES.md` as above.
3. `dotnet restore WayfarerWanderer.slnx --force-evaluate --configfile vendor/passenger/nuget.config`, then the locked
   restore from the README to check the lock files.
4. Fix the two breaks above in `Program.cs`, `Shell/Theme/PlatformWidths.cs` and `Shell/Vcs/VcsController.cs`. Then
   `copies --restamp` those three files `--to v0.4.6`. For `VcsController.cs` (and its twin `GitAsking.cs`), restamp only
   once all of upstream's change to them is ported in Phase 2.
5. Build and run all tests. Fix any upstream literal `NoPassengerInUiTests` reports with `Product.Name` or neutral
   words. The new literals that name Passenger are: `Editor/CodeFonts.cs` `UnreadableWhy` ("a font Passenger cannot
   draw", shown in Settings); `Core/ThisCopy.cs`'s four `FormatException` messages and its `MacBundles.Of(…, "Passenger")`
   path; and the `PassengerLog.Write` lines in `Core/SdkTemporary.cs` and `Core/UserTemporary.cs`.
6. Commit as "Bring vendored Passenger from v0.4.2 to v0.4.6 (494009d7)", listing taken, merged and conflicted files
   as `9330941` does.

What this phase gives Wayfarer without other work:

- **Avalonia 12.2**: synaptics two-finger scrolling on Linux, a Windows paste that waits for the clipboard, Linux
  windows that no longer snap back to an earlier size.
- **Editor**: folding by level and recursively (`EditorActions.FoldRecursively`, `UnfoldToLevel1..5`,
  `UnfoldAllToLevel1..5`, with keys in every Editor keymap). Also cheaper drawing (a line's runs shaped together), the
  extra Editor-keymap bindings (Shift+Delete, Shift+Insert, Ctrl+Insert…), and Vim mode matching Vim 9.2 in hundreds of
  cases (visual `is`/`as`, counted inserts, `.`, block `A`, `J` with marks, `j`/`k` after a failed motion, put over
  an empty text).
- **AltGr vs Ctrl+Alt on Windows** (#2209), in the editor and the terminal.
- **Terminal**: bash keeps the user's own `PROMPT_COMMAND`, and zsh works with `setopt nounset` (#2131, #2135).
- **Git (library side)**: batched staging, unstage keeps moves, `.gitignore` answers from git (`GitIgnores`),
  `.gitattributes` names (`GitAttributeNames`), the diff's "LF added at the end" note fixed (#2150).
- **Windows program lookup** (#2265): git and every program found by name are also found on the user's own `Path` when
  the process was started without it, as after a Scoop install. This helps Wayfarer find `git` and `java`.
- **Core**: cheaper idle (#2359, #2360), folder walks that don't follow links (#2346), `EditorConfig` reading as
  Roslyn and editorconfig.org do.
- **Grammars**: `gitattributes.tmLanguage.json` added (wire it into a Wayfarer `Language` to colour `.gitattributes`).

## Phase 1 outcome

Applied as planned, with one change: **Avalonia stays at 12.1.6.** The trial's single clean run was luck. In the real
checkout the test host crashed in HarfBuzz text shaping (`hb_shape_full` under `CodeEditor.Format`) in 3 of 5 full runs
on 12.2.0, against 0 of 5 on 12.1.6. Undoing upstream's shaping change (`43e51aa4`) didn't stop it. The details, and how
to lift the pin, are in `docs/todo.md` under "Avalonia is held at 12.1.6".

So from the "What this phase gives" list below, Avalonia 12.2's fixes (synaptics scrolling, the Windows clipboard wait,
Linux window sizes) and the AltGr-vs-Ctrl+Alt fix (#2209) wait for the pin to lift. Everything else arrives.
`Keymap.HeldAsCtrlAlt` answers false, which is v0.4.2's behaviour.

## Phase 2 outcome

Applied in four commits, one per group. `copies --to v0.4.6` now lists only `Shell/Welcome/RecentShortcuts.cs`, left
for Phase 4's portable copies. Where it differs from the plan above:

- **2a.** The Branches panel's Show Diff with Working Tree was never wired in Wayfarer; it is now, with the stash's.
  Create Git Repository keeps Wayfarer's JVM `.gitignore` (now `RepositoryFiles.GitIgnore`).
- **2b.** Next and Previous Split are left out: Wayfarer's editor does not split. The keymap audit leaves out the
  numbered bookmarks, Find Word at Caret, Find in Selection, Incremental Search and the `.gitignore` actions. The frame
  actions are in `EditorWindow.Frame.cs`; Code › Folding is in `MainMenuPlaces` and `EditorWindow.MainMenu.cs`.
  `PopupFrame.Resizable` came over but nothing uses it yet (upstream uses it in its Errors popup).
- **2c.** The empty-folder chevron reads the disk alone, as Wayfarer has no evaluated-project folders. `.gitattributes`
  files are coloured (a new `Language`). The navigation bar, Settings and C#-only changes had nothing to take.
- **2d.** New Project's **Create Git repository** is off by default, as in IntelliJ, and offers `.gitattributes` and
  `.editorconfig` (`RepositoryFiles`, Wayfarer's own JVM texts); every starter already writes its `.gitignore`. The
  choices are kept in `newProject.json` (`RepositoryChoices`). `StateStore` is restamped, its portable-copy part
  (`ThisCopy.Data`) still Phase 4's.

## Phase 3: `.gitignore`, `.gitattributes` and `.editorconfig` help (#2140), optional

The libraries arrive in Phase 1 (`Vcs/GitIgnores.cs`, `Vcs/GitAttributeNames.cs`, `Text/EditorConfig.cs`, the

- `CSharp/GitIgnoreAssist.cs`, `CSharp/GitAttributesAssist.cs`: language-agnostic despite the folder. Completion of

the size of this phase depends on that hook.

## Phase 4: portable copies and updates (#2153, #2300), optional

- **Portable copy** (#2153): with a `data` folder beside the executable, the copy keeps all its state there and writes
  nothing to the user's folders or the system's recent lists. `Core/ThisCopy.cs` arrives in Phase 1, but it hard-codes
  `Passenger` (the macOS bundle) and `passenger` (the Linux launcher). Change those to `Product.ProgramName`. Then port
  the App side (`Program.cs`, `State/StateStore.cs`, `Settings/AppSettings.cs` and the updater's "a portable copy
  updates by your hand"), and add a portable zip to `tools/package-release.py` and the release pipeline plan
  (`docs/superpowers/plans/2026-11-25-release-pipeline.md`).
- **Windows updates retry** (#2300): when Update.exe is refused because something holds the install folder, retry up
  to three times as the app closes, and show Velopack's own reason on the next start. Upstream added
  `Updates/UpdateHandOff.cs` and `Updates/VelopackLog.cs` and changed `Updater.cs`, `VelopackUpdater.cs`, `Releases.cs`,
  `LinuxUpdater.cs` and `Program.cs`. Wayfarer's `src/WayfarerWanderer.App/Updates/*` are adapted from Passenger but
  carry only "Adapted from vendored Passenger", **with no commit stamp**, so `copies` never lists them. Diff them by hand
  against `v0.4.2..v0.4.6`. While there, give them proper `From Passenger 8a1df7e4 src/Passenger.App/Updates/…` stamps
  so future updates track them.
- **Package-manager marker** (`package-manager` file, WinGet): only once Wayfarer ships through a package manager.

## Trial test run

After the update, the notices fix and the two ports, `dotnet test tests/WayfarerWanderer.Tests -c Debug --no-build`
gave **366 passed, 30 skipped, 1 failed** (397 in all, 6 min 28 s). The skips are the environment-gated cases (language
servers, first-start pictures) that skip on main too.

The one failure is `NoPassengerInUiTests.NoLiteralWayfarerBuildsSaysPassenger`, on exactly the eight literals listed
in Phase 1 step 5: `CodeFonts.cs:28`, `SdkTemporary.cs:77`, `ThisCopy.cs:49, 68, 80, 92, 108` and `UserTemporary.cs:100`.
The theme, Welcome, editor-host and Git tests all pass on Avalonia 12.2 and the new libraries. So Phase 1 is the
update, the notices merge, the two ports and these eight strings.
